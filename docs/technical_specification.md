# Техническое задание по ГОСТ 34.602-2020
## Автоматизированная информационная система для магазина кастомных ПК

---

## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1. Наименование системы
Автоматизированная информационная система (АИС) «Магазин кастомных ПК»

### 1.2. Заказчик и разработчик
- **Заказчик**: Магазин кастомных ПК
- **Разработчик**: [Наименование организации-разработчика]

### 1.3. Область применения
Система предназначена для автоматизации бизнес-процессов магазина по сборке и продаже кастомных персональных компьютеров, включая:
- управление заказами клиентов;
- учёт комплектующих и складских остатков;
- управление сборочными заданиями;
- ведение клиентской базы;
- формирование отчётности.

### 1.4. Правовые основы разработки
Разработка системы осуществляется в соответствии с:
- ГОСТ 34.602-2020 «Техническое задание на создание автоматизированной системы»;
- Федеральным законом № 152-ФЗ «О персональных данных»;
- Гражданским кодексом Российской Федерации.

---

## 2. НАЗНАЧЕНИЕ И ЦЕЛИ СОЗДАНИЯ СИСТЕМЫ

### 2.1. Назначение системы
АИС предназначена для автоматизации деятельности магазина кастомных ПК и обеспечения:
- регистрации и ведения учёта клиентов (физических и юридических лиц);
- оформления и отслеживания заказов на сборку ПК;
- управления складскими запасами комплектующих;
- распределения задач между сотрудниками сборочного цеха;
- контроля качества и сроков выполнения заказов;
- формирования аналитической отчётности.

### 2.2. Цели создания системы
1. Повышение эффективности обработки заказов.
2. Снижение количества ошибок при комплектации заказов.
3. Оптимизация складских запасов.
4. Улучшение качества обслуживания клиентов.
5. Сокращение времени сборки ПК за счёт оптимального распределения задач.
6. Обеспечение прозрачности бизнес-процессов.

---

## 3. ТРЕБОВАНИЯ К СИСТЕМЕ

### 3.1. Требования к структуре и функционированию

#### 3.1.1. Подсистемы АИС
Система состоит из следующих подсистем:

**а) Подсистема управления пользователями:**
- регистрация и авторизация пользователей;
- управление ролями и правами доступа;
- ведение журнала аудита действий.

**б) Подсистема управления клиентами:**
- регистрация клиентов (физических и юридических лиц);
- хранение контактной информации;
- история взаимодействий с клиентом.

**в) Подсистема управления заказами:**
- создание и редактирование заказов;
- отслеживание статуса заказа;
- расчёт стоимости заказа;
- формирование документов по заказу.

**г) Подсистема управления сборкой:**
- создание сборочных заданий;
- назначение исполнителей;
- контроль этапов сборки;
- фиксация времени начала и завершения работ.

**д) Подсистема управления складом:**
- учёт комплектующих;
- мониторинг остатков на складах;
- проведение инвентаризации;
- перемещение товаров между складами.

**е) Подсистема отчётности:**
- формирование отчётов по продажам;
- отчёты по выполнению сборочных заданий;
- анализ складских остатков;
- аудит изменений в системе.

#### 3.1.2. Режимы функционирования
- **Рабочий режим**: круглосуточная доступность для веб-клиентов, рабочее время (8:00–20:00) для десктоп-приложения сотрудников.
- **Режим технического обслуживания**: еженедельно, воскресенье 02:00–04:00.

### 3.2. Требования к численности и квалификации персонала

#### 3.2.1. Категории пользователей
| Роль | Описание | Требуемая квалификация |
|------|----------|------------------------|
| Администратор | Полное управление системой, пользователями, настройками | Опыт работы с АИС, знание основ информационной безопасности |
| Менеджер | Работа с заказами, клиентами, складом, отчётность | Опыт работы в сфере продаж компьютерной техники |
| Сборщик | Выполнение сборочных заданий, обновление статусов | Технические навыки сборки ПК, внимательность |
| Клиент | Оформление заказов через веб-интерфейс | Базовые навыки работы с браузером |

#### 3.2.2. Требования к подготовке персонала
- Проведение вводного инструктажа (2 часа).
- Предоставление руководства пользователя.
- Доступ к справочной системе в режиме онлайн.

### 3.3. Требования к надёжности

#### 3.3.1. Показатели надёжности
- Коэффициент готовности: не менее 0,99.
- Среднее время восстановления: не более 2 часов.
- Среднее время наработки на отказ: не менее 720 часов.

#### 3.3.2. Требования к сохранности данных
- Ежедневное автоматическое резервное копирование БД.
- Хранение резервных копий в течение 30 дней.
- Защита от несанкционированного доступа (ролевая модель).

### 3.4. Требования к информационной безопасности

#### 3.4.1. Защита данных
- Хранение паролей в хешированном виде (алгоритм bcrypt или аналог).
- Разграничение прав доступа на основе ролей.
- Протоколирование всех критических операций.

#### 3.4.2. Защита от угроз
- Валидация всех входных данных.
- Защита от SQL-инъекций.
- Использование HTTPS для веб-части.

### 3.5. Требования к техническому обеспечению

#### 3.5.1. Серверная часть
- ОС: Windows Server 2019 / Linux Ubuntu 20.04 LTS.
- СУБД: Microsoft SQL Server 2019 / PostgreSQL 13+.
- ОЗУ: не менее 8 ГБ.
- Дисковое пространство: не менее 100 ГБ.

#### 3.5.2. Клиентская часть (десктоп)
- ОС: Windows 10/11.
- Фреймворк: .NET 6.0 или выше.
- ОЗУ: не менее 4 ГБ.
- Разрешение экрана: не менее 1280×720.

#### 3.5.3. Клиентская часть (веб)
- Браузеры: Chrome 90+, Firefox 88+, Edge 90+, Safari 14+.
- Поддержка JavaScript и cookies.

### 3.6. Требования к программному обеспечению

#### 3.6.1. Технологии разработки
- **Десктоп-приложение**: C#, WPF или WinForms, .NET 6+.
- **Веб-приложение**: ASP.NET Core MVC или Blazor.
- **СУБД**: Microsoft SQL Server.
- **ORM**: Entity Framework Core.

#### 3.6.2. Сторонние библиотеки
- AutoMapper – для маппинга DTO.
- FluentValidation – для валидации данных.
- Serilog – для логирования.
- xUnit/NUnit – для тестирования.

### 3.7. Требования к документации
В составе проекта должна быть предоставлена следующая документация:
- Руководство администратора.
- Руководство пользователя.
- Описание базы данных (ER-диаграмма, схема данных).
- Инструкция по установке и развёртыванию.
- Технический отчёт о тестировании.

## 4. СТАДИИ И ЭТАПЫ РАЗРАБОТКИ

### 4.1. Этапы разработки

| Этап | Наименование | Продолжительность | Результат |
|------|--------------|-------------------|-----------|
| 1 | Предпроектный анализ | 2 недели | ТЗ, модель бизнес-процессов |

| 5 | Разработка складского модуля | 3 недели | Учёт остатков, инвентаризация |

### 4.2. Порядок контроля и приёмки
- Промежуточный контроль после каждого этапа.
- Опытная эксплуатация в течение 14 дней.
- Подписание акта приёмки после устранения замечаний.
